# 내담리 (dokseo-toron)

사적 월간 독서모임을 위한 온라인 토론 기록 앱. 매달 돌아가며 책을 정하고, 논제를 올리고, 서로 답을 남기고, 별점을 매기는 걸 구글 문서 대신 이 앱에서 한다.

- **배포 사이트**: https://bookdebate.vercel.app
- **이 프로젝트가 만들어진 과정(바이브 코딩 정리)**: [`docs/VIBE_CODING.md`](docs/VIBE_CODING.md)
- **배경/설계 결정 상세**: `docs/` 아래 문서(`SPEC.md`/`SCHEMA.md`/`SECURITY.md`/`DECISIONS.md`/`RETENTION.md`)와 `독서토론앱.md` 참고. 코드를 다루는 에이전트(Claude Code 등)를 위한 요약은 `CLAUDE.md`.

## 사용법 (참여자)

### 1. 로그인

1. 접속 주소를 열면 로그인 화면이 뜬다.
2. **공통 암호**를 입력한다(모임 단톡방 등으로 공지받은 암호). 5회 이상 틀리면 잠시 후 다시 시도해야 한다.
3. 암호가 맞으면 참여자 이름이 버튼으로 쭉 나온다. 본인 이름을 누르면 로그인된다.
4. 한 번 로그인하면 90일 동안 다시 로그인할 필요가 없다.

### 2. 회차 목록 (첫 화면)

- 맨 위에 **진행 중인 회차**가 카드로 나온다 — 책 제목, 모임까지 남은 일수, "몇 명 중 몇 명 작성 완료", 내 답변 작성 현황.
- 아래로 **지난 회차**가 연도별로 나온다. 눌러서 예전 논제와 답변을 다시 볼 수 있다(아카이브).

### 3. 회차 상세 화면

카드를 누르면 그 회차의 논제 화면으로 들어간다. 별도 보기 탭은 없다 — 왼쪽에 책 정보/참여 현황/논제 목차(사이드바), 오른쪽에 모든 논제가 순서대로 세로로 쭉 나열된 화면 하나뿐이다(스트림). 화면이 좁으면(휴대폰 등) 사이드바가 상단의 가로 요약 바로 바뀌고, 논제 목차는 눌러서 펼치는 아코디언이 된다. 사이드바(또는 요약 바)의 논제 목차를 누르면 그 논제로 바로 스크롤 이동한다.

각 논제 헤더에는 유형 배지(자유/발췌/힘든 구절/찬반/부록)가 붙고, 선택 참여 논제는 "선택" 배지가 함께 붙는다. 제목은 답변 본문보다 뚜렷하게 크고 굵게 표시되며, 헤더 아래 구분선으로 답변 영역과 나뉜다 — 논제 5개를 스크롤하며 봐도 어디부터 새 논제인지 한눈에 구분된다.

논제에는 다섯 가지 종류가 있다. 이 앱을 쓰는 동안 화면에서 실제로 보게 될 형태는 아래와 같다.

- **자유 논제**: 참여자별 답변 카드가 나란히 나온다. 내 카드는 항상 맨 앞, 테두리가 굵다. 카드를 누르면 그 자리에서 바로 답변을 쓰거나 고칠 수 있다. 전원 참여가 전제다.
- **발췌 논제**: 참여자별로 "발췌문 + 고른 이유"가 세로로 쌓인다. 한 사람이 여러 개를 올릴 수 있다 — 아직 안 올렸다면 "내 발췌 추가하기", 이미 올렸다면 그 아래 "발췌 추가하기" 버튼으로 계속 늘려간다. 각 발췌 아래에는 "+ 사유 더하기"가 있어서, 그 발췌에 대해 짧게 내 생각을 덧붙일 수 있다(내 발췌에 내가 덧붙이는 것도 가능). 전원 참여가 전제다.
- **힘든 구절 논제**: 구조는 발췌 논제와 같지만(구절 + "저는 이리 생각했는데…") 선택 참여이고, 1인 1개만 올릴 수 있다 — 안 쓴 사람의 카드는 아예 나오지 않는다. 댓글 영역("같이 생각해 보니")은 **모임 당일부터** 열린다 — 그 전에는 입력창 대신 안내 문구만 보인다.
- **찬반 논제**: 누군가 한 명이 "논제 올리기"로 구체적인 장면/논제를 올리면 그 사람이 발제자가 된다. **게시물이 아직 없어도** 각자 "나는 OO" 버튼으로 미리 입장을 밝히고 이유를 남길 수 있다 — 나중에 누군가 실제 게시물을 올려도 미리 적어둔 입장/이유는 그대로 남는다. 게시물이 있으면 그 아래 "나는 OO" 버튼으로 즉시 입장을 밝히고, 원하면 이유도 따로 남길 수 있다(선택).
- **부록 논제**: 참여 제한이 없고, 한 사람이 여러 개를 올릴 수 있다. "부록 논제 올리기"를 누르면 제목(선택)+본문으로 새 글을 추가한다.
- 별점이 있는 논제(보통 첫 번째 논제)에는 별을 눌러 평가를 남길 수 있다. **0.5점 단위**로 매길 수 있다 — 별 왼쪽 절반을 누르면 0.5점, 오른쪽 절반을 누르면 1점씩 올라간다. 키보드로도(←/→ 화살표) 조작할 수 있다.
- 자유/발췌/힘든 구절/부록 논제의 답변, 그리고 모든 댓글은 **저장 버튼을 눌러야** 저장된다(자동저장 아님, 찬반 논제의 입장 버튼과 별점만 예외 — 누르는 즉시 저장된다). 저장하면 "저장됨 · 방금"이 잠깐 뜬다.
- 본인이 쓴 답변/댓글은 삭제할 수 있다. 발췌·힘든 구절·찬반 게시물·부록 글을 지우면 그 아래 달린 댓글도 같이 지워지므로, 지우기 전에 몇 개가 같이 지워지는지 알려준다.
- 한 번에 편집기 하나만 열 수 있다 — 다른 논제나 다른 글을 편집하려고 하면, 저장 안 한 내용이 있을 때 확인 창이 뜬다.
- "참여 현황"(N명 중 M명 작성)은 자유/발췌 논제만 센다 — 힘든 구절/찬반/부록은 선택 참여라 이 집계에서 빠진다(논제 목차에 "선택" 표시로 안내).

### 4. 공유 문구

회차 상세 화면 오른쪽 위 "공유 문구 복사" 버튼을 누르면 아래 형식 문구가 클립보드에 복사된다. 단톡방에 바로 붙여넣으면 된다.

```
📖 『책 제목』 논제가 올라왔습니다
모임: 모임일 요일
작성: n/전체명 완료 · 마감 마감일
https://bookdebate.vercel.app/s/회차ID
```

### 5. 내 글

헤더의 "내 글"을 누르면 지금까지 내가 쓴 모든 답변과 댓글(사유더하기/같이 생각해 보니/의견 남기기 전부 포함)을 회차 역순으로 모아 볼 수 있다.

### 6. 회차 상태에 따른 차이

- **작성 중(open)**: 답변/사유더하기를 자유롭게 쓰고 고치고 지울 수 있다.
- **마감(closed)**: 새로 쓰거나 고칠 수 없다. 지난 내용을 읽는 것만 가능하다. 늦게라도 써야 하면 관리자에게 재오픈을 요청한다.
- **준비 중(draft)**: 관리자가 아직 논제를 세팅하는 중이다. 내용은 미리 볼 수 있지만 답변은 못 쓴다.

### 7. 관리자 전용 기능

헤더에 "관리자" 링크가 보이면 관리자 계정이다(현재는 참여자 전원이 관리자다 — 아래 참고). `/admin` 하위에서:

- **회원**: 참여자 추가/수정, 별칭(축약 이름) 등록, 비활성화(탈퇴 대신).
- **책**: 제목/저자/표지/메모 관리.
- **회차**: 새 회차 만들기 — 책, 모임일, 마감일, 선정자/진행자를 정하고, 논제를 "템플릿에서 시작"하거나 "이전 회차 구조 복제"로 한 번에 채울 수 있다(직접 하나씩 만들 필요 없음). 상태(준비 중/작성 중/마감)도 여기서 바꾼다. 찬반 논제의 선택지(기본 "찬성,반대,모르겠다")도 자유롭게 고칠 수 있다.
- **템플릿**: 매달 반복되는 논제 구성(예: "한 문장 요약" + "발췌 나누기")을 저장해뒀다가 새 회차에 바로 적용.
- **이관**: 구글 문서에서 복사한 지난 회차 텍스트를 붙여넣으면 자동으로 논제/답변/사유더하기로 변환한다. 저장 전에 반드시 미리보기(몇 개가 만들어지는지)를 보여주고, 이름이 안 맞는 경우 기존 회원과 연결하거나 새로 만들지 직접 고르게 한다.

### 자주 묻는 질문

**Q. 암호를 잊었어요.**
관리자에게 물어본다. 공통 암호는 앱에서 확인할 수 없다.

**Q. 답변을 잘못 썼어요.**
저장 후에도 카드를 다시 눌러 고칠 수 있다(회차가 "작성 중"일 때만).

**Q. 남의 발췌에 사유를 여러 번 달 수 있나요?**
가능하다. 개수 제한은 없다.

**Q. 남이 만든 답변/댓글을 지울 수 있나요?**
지금은 참여자 전원이 관리자 권한이라 서로의 글을 수정·삭제할 수 있다 — 6명이 서로 아는 사적 모임이라는 신뢰 관계 위에서 의도적으로 그렇게 정했다(`docs/DECISIONS.md` "전원 관리자 권한 부여" 절 참고).

**Q. 모바일로도 쓸 수 있나요?**
가능하지만 이 앱은 데스크톱 사용을 기준으로 만들어졌다. 화면이 좁으면 좌측 사이드바가 상단 요약 바로 바뀌고 논제 목차는 눌러서 펼쳐야 한다.

## 개발 · 배포

### 로컬 실행

```bash
npm install
cp .env.example .env.local   # 값 채우기, 아래 "환경변수" 참고
npm run dev
```

`http://localhost:3000`에서 확인한다. 최초 1회는 Supabase 프로젝트에 스키마와 시드를 넣어야 한다:

```bash
# supabase/migrations/*.sql 을 Supabase 대시보드 SQL Editor에서 번호 순서대로 실행
# 이어서 supabase/seed.sql 실행
```

공통 암호 해시는 아래로 만든다(값에 `$`가 들어가므로 `.env.local`에 넣을 때 `\$`로 이스케이프해야 한다 — `.env.example` 주석 참고):

```bash
npm run hash-password -- <원하는 암호>
```

### 환경변수

| 이름 | 용도 | 클라이언트 노출 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 URL | 가능 |
| `NEXT_PUBLIC_SITE_URL` | 공유 문구용 절대 URL | 가능 |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 DB 접근 | **절대 금지** |
| `SITE_PASSWORD_HASH` | 공통 암호 bcrypt 해시 | 금지 |
| `SESSION_SECRET` | JWT 서명 키 (32자 이상) | 금지 |
| `REQUIRE_MEMBER_PIN` | 개인 PIN 사용 여부 (기본 false) | 금지 |
| `CRON_SECRET` | keep-alive 인증 | 금지 |

값의 위치: Supabase 대시보드 Project Settings > API(URL, service-role 키). 나머지는 직접 생성한다.

### 배포 (Vercel)

1. GitHub 저장소를 Vercel 프로젝트에 연결한다.
2. 위 환경변수 전부를 Vercel 프로젝트 설정에 등록한다(`SITE_PASSWORD_HASH`는 로컬과 달리 **이스케이프하지 않은** 원본 값을 넣는다 — Vercel은 `$` 변수 치환을 하지 않는다).
3. `vercel.json`에 정의된 `/api/keep-alive` cron(매일 03:00 UTC)이 자동으로 등록된다. Vercel이 `CRON_SECRET` 환경변수를 이용해 자동으로 `Authorization: Bearer` 헤더를 붙여 호출한다 — 별도 설정 불필요.
4. Vercel Hobby 플랜은 cron을 하루 1회까지만 허용한다. `vercel.json`의 스케줄을 하루 2회 이상으로 바꾸면 배포 자체가 실패하니 주의.

### 배포 전 점검

`docs/SECURITY.md`의 "서버 측 필수 검증 체크리스트"를 따른다. 특히:

- `.next` 빌드 산출물에 `SUPABASE_SERVICE_ROLE_KEY`의 실제 값이 없는지 확인(환경변수 이름 자체는 서버 전용 청크에 나타나는 게 정상이다).
- 클라이언트 컴포넌트(`"use client"`)에서 `@supabase/supabase-js`를 직접 import하는 곳이 없는지 확인.
- 모든 Server Action의 첫 줄이 `requireSession()`/`requireAdmin()`을 호출하는지 확인.
- `supabase/migrations/`에 작성만 되고 아직 프로덕션에 적용되지 않은 파일이 있는지 확인(각 파일 상단 주석에 적용 여부가 적혀 있다).

### 기술 스택

Next.js(App Router) + TypeScript + Tailwind CSS, Supabase(Postgres, service-role 전용 접근), Vercel 배포.
