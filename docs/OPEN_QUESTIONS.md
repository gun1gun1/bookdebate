# OPEN_QUESTIONS.md

Phase 0 단계에서 임의로 판단하지 않고 질문으로 남겨둔 항목들. Phase 1 이후 구현에 들어가기 전, 이 목록에 답을 정하고 결정된 내용은 DECISIONS.md로 옮긴다.

## 데이터/정책 — 답변 완료 (2026-08-16)

1~6번은 답이 정해졌다. 결정 내용과 이유는 DECISIONS.md의 "Phase 0 후속 결정" 절 참고, 반영된 스키마/정책 변경은 SCHEMA.md·SECURITY.md·SPEC.md에도 각각 반영했다.

1. 본인 answer 삭제 → **허용, 하위 replies도 함께 삭제**(CASCADE).
2. `members.aliases` 겹침 검증 → **하지 않음**(규모가 작아 관리자 주의에 맡김, 의도적으로 미검증).
3. `kind != 'excerpt'`인 topic의 answer에 reply → **excerpt에서만 Server Action이 허용**, 그 외에는 서버가 거부.
4. 본인 excerpt answer에 본인이 reply 다는 것 → **허용**.
5. `closed` 이후 새 답변/사유더하기 작성 → **완전히 막음**.
6. `draft` 상태 회차 노출 → **논제까지 보이되 작성만 막음**.

5번과 6번은 하나의 규칙으로 통합했다: **답변/사유더하기 쓰기는 `session.status === 'open'`일 때만 허용**(draft와 closed 둘 다 이 조건으로 자동으로 막힌다). 자세한 내용은 DECISIONS.md 참고.

## 관리자/운영

7. **관리자를 여러 명 둘 수 있는가, 또는 두어야 하는가?** `members.role`은 이미 `'admin'`을 지원하지만, 현재 관리자 1명을 전제로 설계했다(RETENTION.md의 "관리자가 지치면 앱이 죽는다"는 가설도 1인 관리자를 암묵적으로 가정). 관리자가 2명이면 "회차 템플릿에서 30초 세팅" 같은 리텐션 장치의 필요성 자체가 줄어들 수 있어, 이 답에 따라 다른 우선순위가 바뀔 수 있다.
8. **개인 PIN(`REQUIRE_MEMBER_PIN=true`)을 켰을 때, PIN을 분실한 멤버는 어떻게 복구하는가?** 관리자가 `pin_hash`를 초기화하는 화면이 필요한지, 아니면 이 스위치를 켤 계획이 실제로는 없는지(스키마/코드만 준비해두고 영구히 `false`로 둘 것인지).
9. **모임이 연기/취소됐을 때 흐름은 무엇인가?** `sessions.meets_at`을 관리자가 수정하면 되는지, 아니면 별도 "연기됨" 상태나 참여자 재공지(공유 문구 재생성) 절차가 필요한지. RETENTION.md의 공유 문구는 "논제가 올라왔습니다" 시나리오만 다루고 변경 공지는 다루지 않는다.
10. **붙여넣기 이관을 같은 회차에 두 번 실행하면 어떻게 되는가?** 미리보기는 있지만(SPEC.md), 중복 실행 시 기존에 이미 이관된 논제/답변과 겹치는지 감지해서 경고할지, 아니면 매번 새로 추가되는 것을 관리자의 주의에만 맡길지.

## UI/스케일

11. **`excerpt_text`, `excerpt_reason`, `body`, reply `body`에 길이 제한을 둘 것인가?** 원본이 자유 서술형이라 제한을 두면 사용자 경험을 해칠 수 있지만, 완전히 무제한이면 매트릭스 뷰의 "첫 문장 20자" 미리보기나 UI 레이아웃이 극단적으로 긴 입력에 어떻게 반응할지 확인이 필요하다.
12. **멤버 이름(`members.name`)을 변경하면 과거 회차의 답변/사유더하기 표시도 새 이름으로 바뀌는가?** 아카이브 성격상 "당시 이름"을 보존해야 한다는 요구가 있을 수도 있다(예: 개명, 별명 변경). 현재 스키마는 `answers`/`replies`가 `member_id`만 참조하므로 자동으로 최신 이름이 반영된다 — 이것이 의도인지 확인 필요.
13. ~~별점(`ratings`)이 화면상 논제 1번에 붙어 있지만...~~ **Phase 4에서 해결**: 특정 순번이 아니라 `has_rating=true`인 논제에 위젯을 붙이는 것으로 결정했다. `docs/DECISIONS.md` "Phase 4" 절 참고.
14. **`difficult`(힘든 구절)도 `excerpt`처럼 1인 다건을 허용할 것인가?** R1-f(2026-08-22)에서 `excerpt`는 다건을 허용했지만(`docs/DECISIONS.md` "R1-f" 절), `difficult`는 그 턴의 결정 대상에서 제외했다 — 선택 참여 kind라 다건의 실사용 수요가 아직 확인되지 않았다.

## 답변이 정해지기 전까지

데이터/정책 1~6번은 답이 정해졌으므로 Phase 1 착수를 막는 항목은 이제 없다. 7~13번(관리자/운영, UI/스케일)은 Phase 2~4 진행 중 해당 화면을 만들 때 확인해도 늦지 않다.
