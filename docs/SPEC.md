# SPEC.md

독서토론 앱의 화면, 기능, 사용자 흐름, 상태 전이 명세. 데이터 구조는 SCHEMA.md, 보안 요구사항은 SECURITY.md 참고.

**[R1]** 회차 상세 화면(화면 2)이 3탭 구조에서 사이드바+스트림 구조로 전면 개편됐고, 논제 유형이 5종으로 늘었다(`docs/REFACTOR_PLAN.md` 참고). 아래 내용은 그 이후 상태를 기술한다.

## 이용자

- 참여자 5~8명 (고정 멤버, 40~50대), 주 사용 환경은 데스크톱, 모바일은 보조.
- 관리자 1명 (참여자 중 한 명이 겸함, `members.role = 'admin'`).
- 사용 빈도: 월 1회 집중, 나머지 기간은 유휴 — 로그인 세션 유지 기간(90일), keep-alive cron 등 다른 설계 결정의 전제가 되는 사실.

## 인증 흐름

1. `/login` 진입 — 비로그인 상태로 다른 어떤 경로에 접근해도 여기로 리다이렉트된다.
2. 1단계: 공통 암호 입력. 틀리면 실패 카운트 증가(`login_attempts`), 10분 내 5회 실패 시 10분간 차단.
3. 2단계: 명단에서 본인 이름을 버튼 그리드로 선택(드롭다운 아님).
4. (`REQUIRE_MEMBER_PIN=true`인 경우만) 4자리 PIN 입력 추가.
5. 세션 쿠키 발급(JWT, httpOnly, 90일). 이후 90일간 재로그인 불필요.
6. 헤더 좌측에 "내담리" 로고 링크(**[R1]**), 우측에 현재 로그인한 이름 표시, 로그아웃 버튼.

상태 전이: `비로그인 → 암호 확인됨(임시) → 신원 확정(세션 발급) → 로그인 상태`. 암호만 맞고 이름을 선택하지 않은 "임시" 상태는 서버 세션을 발급하지 않는다(클라이언트 단계 전환일 뿐).

## 화면 1 — `/` (회차 목록)

- 최상단에 히어로 이미지(`public/brand/naedamri-hero.png`, 표시 폭 560px 이하). **[R1]**
- 진행 중(`status='open'`) 회차를 상단에 큰 카드로: 책 표지(`BookCover`, 없으면 제목 이니셜 플레이스홀더), 제목, 모임일까지 남은 일수, 참여 현황("5명 중 3명 작성"), 내 상태("내 답변 2/4 작성").
- 지난 회차(`status='closed'`)는 아래에 연도별 그룹으로 목록.
- "작성"의 정의: 해당 회차의 **전원 참여 전제 논제(`free`/`excerpt`, `lib/topics.ts`의 `isMandatoryKind()`)** 전부에 대해 그 참여자의 `answers` 행이 존재하고 "미작성 판정"(SCHEMA.md 참고)을 통과한 것. **[R1]** `difficult`/`choice`/`appendix`는 선택 참여라 이 집계의 분모·분자에서 제외한다.

## 화면 2 — `/s/[id]` (회차 상세) **[R1 전면 재작성]**

URL은 `/sessions/`가 아니라 `/s/`로 짧게 유지한다. **[R1]** 뷰 전환 탭(논제별/사람별/한눈에)은 제거됐다 — 논제를 한 화면에 순서대로 세로로 나열하는 **스트림** 구조 하나만 있다.

### 레이아웃

- **좌측 사이드바**(`SessionSidebar.tsx`, `xl:` 이상 1280px에서 고정 폭 320px, sticky): 책 표지·제목·저자, 모임일·마감일, 참여 현황, 논제 목차(스크롤 위치에 따라 현재 논제 강조 — `IntersectionObserver`), 공유 문구 복사 버튼.
- **`xl:` 미만(1280px 미만)**: 같은 정보가 상단 가로 요약 바로 전환된다. 논제 목차는 기본 접힘, 클릭하면 펼쳐지는 아코디언(제목+kind 배지).
- **우측 본문**: 논제를 `topics.order_no` 순서대로 전부 세로 스트림으로 렌더링. 각 논제는 `id="topic-{id}"` 앵커를 가져 사이드바 목차 클릭 시 그 위치로 스크롤한다.
- 본문 컬럼 폭은 화면이 넓어도 약 68자(`max-w-[68ch]`)로 고정 — 데스크톱 우선 원칙(CLAUDE.md 참고)에 따라 가독성을 위해 화면 폭을 그대로 다 쓰지 않는다.
- **[R1-f] 논제 헤더**: 각 논제 상단에 kind 배지(`lib/topics.ts`의 `KIND_LABEL` — 자유/발췌/힘든 구절/찬반/부록, 브랜드색 `#F2CB66` 배경)와 선택 참여 kind에는 "선택" 배지(사이드바 목차와 같은 표기)를 달고, 제목을 답변 본문보다 뚜렷하게 큰 굵은 글씨로 키운 뒤 `border-b`로 답변 영역과 구분한다. 논제 사이 간격도 넓혀(`gap-14`) "논제가 다 비슷해 보인다"는 문제에 대응했다. 브랜드색은 배지 같은 구조 요소에만 쓰고 본문 읽기 영역은 흰 배경을 유지한다(CLAUDE.md 원칙).

### 편집기 동시 열림 방지 **[R1 신규]**

스트림 구조에서는 여러 논제의 편집기가 동시에 열릴 수 있어, 화면 밖에 저장하지 않은 편집기가 남아 잊히는 사고가 생길 수 있다. 페이지 전체에서 **편집기 하나만 열리도록 제한**한다(`app/s/[id]/EditorLockContext.tsx`) — 이미 다른 편집기가 열려 있는 상태에서 새 편집기를 열려고 하면 "저장하지 않은 내용이 있습니다. 계속할까요?" 확인창이 뜬다. 탭 닫기/새로고침 시의 `beforeunload` 확인도 편집기가 하나라도 열려 있으면 동작한다.

### 논제 유형별 화면 **[R1: 5종 전부]**

| kind | 컴포넌트 | 참여 방식 | 핵심 동작 |
|---|---|---|---|
| `free` | `FreeView`(`TopicPanel.tsx` 내부) | 전원 참여 전제 | 참여자별 답변 카드가 나란히. 내 카드는 항상 첫 자리, 테두리 강조, 클릭 시 인라인 편집. 미작성자도 빈 카드로 표시. |
| `excerpt` | `ExcerptView`(`TopicPanel.tsx` 내부) | 전원 참여 전제, **[R1-f] 1인 다건 허용** | 참여자별 블록을 세로로 쌓는다. 발췌문(좌측 세로선 + 세리프 인용 서식) → 이유 → "사유 더하기" 스레드. 내 발췌들이 먼저 쌓이고 그 아래 "발췌 추가하기"(하나도 없으면 "내 발췌 추가하기") 버튼, 이어서 다른 참여자들의 발췌. 각 블록은 본인만 수정·삭제. |
| `difficult` | `DifficultView.tsx` | **선택 참여** | 작성자만 나열, 없으면 "내 구절 추가하기" 버튼만(미작성자 카드 없음). 구절(`quote_text`)+이유(`quote_reason`, 입력 라벨 "저는 이리 생각했는데…") 입력. 댓글("같이 생각해 보니")은 모임 당일(KST) 이전에는 입력창 대신 "모임 당일부터 남길 수 있습니다" 안내만 표시. 1인 다건은 아직 미허용(`docs/OPEN_QUESTIONS.md` 14번). |
| `choice` | `ChoiceView.tsx` | **선택 참여, 2단 구조[R1-e], 사전 작성 허용[R1-f]** | answers 행 없음: 참여자 누구나 "논제 올리기"(먼저 올리는 사람이 발제자)와, 게시물 없이도 "나는 {선택지}"로 입장을 미리 밝히는 UI를 함께 보여준다. answers 행 1개(게시물 body 있음/없음 무관): 상단에 게시물(비어 있으면 "아직 논제 게시물이 없습니다" + 누구든 채울 수 있음, 채워져 있으면 원 작성자만 수정), 그 아래 "나는 {선택지}" 버튼 — 클릭 즉시 reply에 저장(별도 저장 버튼 없음, 별점과 같은 패턴). 입장을 밝힌 사람이 있으면 집계 막대 + 진영별 이유(reply.body, 선택 입력) 카드(선택지 3개 이상도 열 너비가 깨지지 않도록 그리드 열 수를 선택지 개수에 맞춘다). 이유는 별도 "이유 남기기/수정"으로 입력(`docs/DECISIONS.md` "R1-e"/"R1-f" 절 참고). |
| `appendix` | `AppendixView.tsx` | **선택 참여, 1인 다건** | "부록 논제 올리기" 버튼이 항상 노출(제한 없음). 제목(선택)+본문. 본인 글만 수정·삭제 가능. |

`free`/`excerpt`/`difficult`/`appendix` 4종은 각 답변 하단에 댓글 스레드(`components/ReplyThread.tsx` 공용 컴포넌트)가 붙는다 — **[R1]** 이전에는 `excerpt`에만 댓글("사유 더하기")을 달 수 있었지만, R1부터는 이 4종 전부 가능하다. 레이블은 kind마다 다르다: `excerpt`="사유 더하기", `difficult`="같이 생각해 보니"(KST 게이트 적용), `free`/`appendix`="의견 남기기"(`docs/DECISIONS.md` "R1: 논제 유형별 reply 레이블 정책" 참고). **[R1-e]** `choice`는 이 공용 스레드를 쓰지 않는다 — 찬반 reply가 "게시물당 참여자 1개, 입장+이유 결합"이라는 별도 규칙을 가지므로 `ChoiceView` 전용 UI(찬반 버튼 + "이유 남기기/수정")로 처리한다.

별점 위젯은 `has_rating=true`인 논제(보통 논제 1번, `free` kind)에 붙는다. **[R1-f]** 0.5 단위 반점을 지원한다 — 별 하나를 좌/우 절반 클릭 영역으로 나눠 즉시 저장하고(`components/StarRating.tsx`), 좌우 화살표 키로도 조작할 수 있다. 참여자별 집계(`components/RatingSummary.tsx`)도 반쪽 별을 표시한다.

**[R1] 제거된 화면**: "사람별 뷰"(`MemberPanel.tsx`), "한눈에 뷰"(`MatrixPanel.tsx`, 데스크톱 전용 매트릭스)는 스트림 구조 도입과 함께 삭제됐다.

## 화면 3 — `/me`

내가 쓴 글 모아보기. 회차 역순, 답변과 댓글을 모두 포함. 읽기 전용. **[R1]** `components/AnswerContent.tsx`가 kind별 answer를 읽기 전용으로 렌더링한다 — `difficult`는 excerpt와 같은 서식에 더해 그 답변에 달린 댓글을 "같이 생각해 보니" 레이블로 함께 보여주고, `appendix`는 제목(있으면)+본문. **[R1-e]** `choice`는 더 이상 별도 분기가 없다 — 이 kind의 answer는 이제 발제자의 게시물 본문뿐이라 다른 kind(`free`)와 같은 기본 렌더(본문만)로 충분하다. 내가 남긴 찬반(입장+이유)은 answer가 아니라 reply이므로, 페이지의 "답변" 목록이 아니라 "댓글" 목록 쪽(`→ {작성자}의 발췌에: {내용}` 형식)에 나타난다.

## 공유 문구 생성

회차 상세 사이드바(또는 좁은 화면의 요약 바)의 버튼. 클릭 시 아래 형식 문구를 클립보드에 복사하고 토스트를 띄운다. 관리자뿐 아니라 모든 참여자가 사용 가능(자세한 배경은 RETENTION.md 참고).

```
📖 『{책 제목}』 논제가 올라왔습니다
모임: {모임일} {요일}
작성: {n}/{전체}명 완료 · 마감 {마감일}
{절대 URL}
```

## 편집 동작 (공통 원칙)

- 자동 저장하지 않는다. 저장 버튼을 명시적으로 둔다. **[R1 예외]** `choice`의 입장 선택과 별점은 클릭 즉시 저장(저장 버튼 없음) — 둘 다 "값을 고르는" 단일 동작이라 별도 확인 단계가 오히려 마찰이라고 판단.
- 저장 후 "저장됨 · 방금"을 3초간 표시.
- 작성 중 이탈 시도 시 확인창(브라우저 unload 확인 + 편집기 전환 가드 — 위 "편집기 동시 열림 방지" 절 참고. **[R1]** 이전에는 뷰/논제 전환에 걸려 있었으나 탭이 사라지며 "편집기 전환" 자체로 대상이 바뀌었다).
- 리치 에디터 없음. `textarea` + `whitespace-pre-wrap`.
- 발췌 서식이 필요한 필드(`quote_text`/`quote_reason` — **[R1]** `excerpt_text`/`excerpt_reason`에서 리네임, `excerpt`와 `difficult`가 공유)만 예외적으로 별도 입력 필드로 분리한다(다른 서식으로 렌더링되므로).
- 본인 answer 삭제는 허용하되(DECISIONS.md 참고), 삭제 시 하위 댓글도 함께 삭제되므로 확인 모달에 "N개도 함께 삭제됩니다"처럼 개수를 명시한다. 개수가 0이면 일반 삭제 확인 문구만 표시.

## 관리자 화면 (`/admin` 하위)

### `/admin/members`

- 이름, 별칭 목록(쉼표 구분 입력 → `text[]` 변환), 역할, 활성 여부.
- 삭제 대신 `is_active = false`로 처리(과거 회차 데이터의 참조 무결성 보존).

### `/admin/books`

- 제목, 저자, 표지 URL, 메모.

### `/admin/sessions`

- 책, 모임일, 마감일, 책 선정자, 진행자, 상태(`draft`/`open`/`closed`).

### `/admin/sessions/[id]/topics` **[R1 갱신]**

- 논제 추가/수정/삭제, 순번은 숫자 입력으로 정렬.
- 유형 선택: `free`/`excerpt`/`difficult`/`choice`/`appendix`(5종, `NewTopicForm.tsx`/`TopicRow.tsx`).
- 유형을 고르면 참여 방식 한 줄 안내가 함께 뜬다 — `free`/`excerpt`="전원 참여 전제입니다", `difficult`/`choice`="선택 참여 논제입니다", `appendix`="누구나 여러 개를 올릴 수 있습니다"(`kindHints.ts`).
- `choice`를 고르면 선택지 입력 필드(쉼표 구분, 기본값 "찬성,반대")가 함께 노출되고 `topics.choice_options`에 저장된다.
- 담당자 지정(선택), 별점 표시 여부 체크박스.
- 답변이 이미 달린 논제를 삭제하려는 시도는 경고 후 차단.

### 회차 템플릿 (`/admin/templates`)

매달 논제 1번(요약+별점)과 2번(발췌 나눔)이 사실상 고정이라는 관찰에서 나온 기능(자세한 배경은 RETENTION.md).

- 논제 묶음을 템플릿으로 저장. 유형 선택은 `/admin/sessions/[id]/topics`와 동일하게 5종. **[R1]** 단, 템플릿 항목에는 `choice_options` 컬럼이 없다 — `choice` 항목이 실제 회차에 적용되면 `topics.choice_options`는 DB 기본값(`{찬성,반대}`)을 받고, 필요하면 관리자가 회차별 논제 수정 화면에서 바꾼다.
- 새 회차 생성 시 "템플릿에서 시작" 선택 가능.
- 기본 템플릿 하나를 시드에 넣는다: 1) `free` · "책을 소개하는 한 문장 요약" · 담당=책 선정자 · 별점 있음, 2) `excerpt` · "인상 깊게 읽은 부분이나 발췌를 이유와 함께 소개해 주세요". **[미완료]** 5논제 구성(difficult/choice/appendix 추가)으로 갱신하는 작업은 아직 안 됐다 — `supabase/seed.sql`은 여전히 이 2논제 그대로다(`REFACTOR_PLAN.md` 4.6절 참고, 남은 작업 상세는 같은 문서 4.6절 끝에 정리).
- 이전 회차를 골라 논제 구조만 복제하는 기능도 포함.

### 붙여넣기 일괄 이관 (`/admin/sessions/[id]/import`)

구글 문서에서 복사한 텍스트를 붙여넣으면 파싱한다. 파싱 규칙과 신뢰 경계는 SECURITY.md와 CLAUDE.md의 "붙여넣기 이관 파서" 절 참고.

**[R1-c2 완료]**: `lib/admin/importParser.ts`는 `free`/`excerpt`/`difficult` 3종을 구조적으로 판정한다(difficult는 "이름"→"힘든 구절" 라벨→`quote_text`→"저는 이리 생각했는데…"→`quote_reason`→"같이 생각하니…"→`이름: 댓글` 반복 형식, `REFACTOR_PLAN.md` 4.8절). `choice`/`appendix`는 kind는 판정하되 구조 파싱은 하지 않고 논제 원문 전체를 "미분류 텍스트"로 미리보기에 보여준다 — 관리자가 수동으로 처리한다(자동 answers/replies 생성 없음). `app/admin/sessions/[id]/import/actions.ts`의 DB insert는 R1-a 컬럼 리네임(`quote_text`/`quote_reason`)에 맞춰 갱신됐다.

흐름:

1. 텍스트 붙여넣기.
2. 서버가 파싱해 미리보기 표시(예: "논제 3개, 답변 15개, 사유더하기 22개를 만듭니다"). 이름 매칭에 실패한 항목은 목록으로 별도 표시하고, 관리자가 기존 멤버에 연결하거나 새로 만들지 선택.
3. 관리자가 확인 버튼을 눌러야 실제 저장이 일어난다. 미리보기 없이 즉시 저장되는 경로는 없다.

## 회차 상태 전이

```
draft → open → closed
        ↑________|   (관리자가 다시 open으로 되돌리는 것도 가능)
```

쓰기 권한은 상태별로 따로 분기하지 않고 **단일 규칙**을 따른다(DECISIONS.md 참고): **answers/댓글의 생성·수정·삭제는 `session.status === 'open'`일 때만 서버가 허용한다.** **[R1]** `difficult`의 댓글("같이 생각해 보니")만 여기에 KST 게이트(모임 당일 0시 이후)가 AND로 추가된다 — SCHEMA.md "difficult 댓글 게이팅" 절 참고. 이 예외 때문에 "다음 회차를 열기 전까지 이전 회차를 닫지 않는다"는 운영 원칙이 생겼다(DECISIONS.md 참고).

- `draft`: 관리자가 논제를 세팅 중. 참여자에게 회차 목록과 논제 내용은 보이지만(완전히 숨기지 않음), 답변/댓글 작성 UI는 비활성화되고 서버도 쓰기를 거부한다.
- `open`: 참여자가 답변/댓글 작성 가능. `/` 상단 카드에 노출.
- `closed`: 작성 마감. 조회(아카이브)는 계속 가능하지만 새 답변/댓글 작성과 기존 것의 수정은 서버가 완전히 거부한다. 늦참자를 구제하려면 관리자가 상태를 다시 `open`으로 되돌려야 한다 — 별도의 "재오픈" 기능을 새로 만들지 않고 기존 상태 변경으로 처리한다. **[R1-c2 완료]** `closed` 전환 직전 "댓글 없는 힘든 구절 N개" 경고(`app/admin/sessions/SessionRow.tsx`, `countUnrepliedDifficultAnswersAction`)가 구현됐다 — `REFACTOR_PLAN.md` 4.10절.
