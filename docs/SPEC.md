# SPEC.md

독서토론 앱의 화면, 기능, 사용자 흐름, 상태 전이 명세. 데이터 구조는 SCHEMA.md, 보안 요구사항은 SECURITY.md 참고.

## 이용자

- 참여자 5~8명 (고정 멤버, 40~50대), 주 사용 환경은 데스크톱, 모바일은 보조.
- 관리자 1명 (참여자 중 한 명이 겸함, `members.role = 'admin'`).
- 사용 빈도: 월 1회 집중, 나머지 기간은 유휴 — 로그인 세션 유지 기간(90일), keep-alive cron 등 다른 설계 결정의 전제가 되는 사실.

## 인증 흐름

1. `/login` 진입 — 비로그인 상태로 다른 어떤 경로에 접근해도 여기로 리다이렉트된다.
2. 1단계: 공통 암호 입력. 틀리면 실패 카운트 증가(`login_attempts`), 10분 내 5회 실패 시 10분간 차단.
3. 2단계: 명단에서 본인 이름을 버튼 그리드로 선택(드롭다운 아님).
4. (`REQUIRE_MEMBER_PIN=true`인 경우만) 4자리 PIN 입력 추가.
5. 세션 쿠키 발급(JWT, httpOnly, 90일). 이후 90일간 재로그인 불필요.
6. 헤더 우측에 현재 로그인한 이름 표시, 로그아웃 버튼.

상태 전이: `비로그인 → 암호 확인됨(임시) → 신원 확정(세션 발급) → 로그인 상태`. 암호만 맞고 이름을 선택하지 않은 "임시" 상태는 서버 세션을 발급하지 않는다(클라이언트 단계 전환일 뿐).

## 화면 1 — `/` (회차 목록)

- 진행 중(`status='open'`) 회차를 상단에 큰 카드로: 책 표지, 제목, 모임일까지 남은 일수, 참여 현황("5명 중 3명 작성"), 내 상태("내 답변 2/4 작성").
- 지난 회차(`status='closed'`)는 아래에 연도별 그룹으로 목록.
- "작성"의 정의: 해당 회차의 모든 `topics`에 대해 그 참여자의 `answers` 행이 존재하고 "미작성 판정"(SCHEMA.md 참고)을 통과한 것.

## 화면 2 — `/s/[id]` (회차 상세)

URL은 `/sessions/`가 아니라 `/s/`로 짧게 유지한다. 상단에 뷰 전환 탭 3개, 현재 뷰는 URL 쿼리(`?view=`)로 관리해 새로고침·공유 시에도 유지된다.

### 논제별 뷰 (기본, `?view=topic`)

- 좌측에 논제 목록 사이드바 고정(데스크톱 1024px 이상). 각 논제에 내 작성 여부를 점으로 표시.
- 우측 본문에 선택된 논제.
- `kind='free'`: 논제 본문 → 별점 위젯(`has_rating`일 때만) → 참여자 답변 카드. 데스크톱 2열 그리드(1440px 이상 3열), 모바일 1열. 내 카드는 항상 첫 자리, 테두리 강조, 클릭 시 인라인 편집(별도 페이지 이동 없음).
- `kind='excerpt'`: 참여자별 블록을 세로로 쌓는다. 블록 구성 = 발췌문(좌측 세로선 + 세리프 인용 서식) → 이유 → 구분선 → "사유 더하기" 스레드(들여쓰기). 내 발췌 블록이 없으면 상단에 "내 발췌 추가하기" 버튼. 모든 발췌 블록(내 것 포함, DECISIONS.md 참고) 하단에 항상 "사유 더하기" 입력창(기본 접힘, 2~3줄).

### 사람별 뷰 (`?view=member`)

- 상단 참여자 탭. 선택한 사람의 전 논제 답변 + 그 사람이 단 사유더하기를 세로로 나열. 읽기 전용.

### 한눈에 뷰 (`?view=matrix`, 데스크톱 전용)

- 행=참여자, 열=논제인 표. 셀에는 작성 여부 아이콘 + 첫 문장 20자. 셀 클릭 시 논제별 뷰의 해당 위치로 이동.
- 진행자가 토론 직전 전체 판을 파악하는 용도. 1024px 미만에서는 탭 자체를 숨긴다.

## 화면 3 — `/me`

내가 쓴 글 모아보기. 회차 역순, 답변과 사유더하기를 모두 포함. 읽기 전용.

## 공유 문구 생성

회차 상세 우상단 버튼. 클릭 시 아래 형식 문구를 클립보드에 복사하고 토스트를 띄운다. 관리자뿐 아니라 모든 참여자가 사용 가능(자세한 배경은 RETENTION.md 참고).

```
📖 『{책 제목}』 논제가 올라왔습니다
모임: {모임일} {요일}
작성: {n}/{전체}명 완료 · 마감 {마감일}
{절대 URL}
```

## 편집 동작 (공통 원칙)

- 자동 저장하지 않는다. 저장 버튼을 명시적으로 둔다.
- 저장 후 "저장됨 · 방금"을 3초간 표시.
- 작성 중 이탈 시도 시 확인창(브라우저 unload 확인 + 앱 내 라우팅 가드).
- 리치 에디터 없음. `textarea` + `whitespace-pre-wrap`.
- 발췌문(`excerpt_text`)만 예외적으로 별도 입력 필드로 분리한다(다른 서식으로 렌더링되므로).
- 본인 answer 삭제는 허용하되(DECISIONS.md 참고), 삭제 시 하위 `replies`(사유 더하기)도 함께 삭제되므로 확인 모달에 "사유더하기 N개도 함께 삭제됩니다"처럼 개수를 명시한다. 개수가 0이면 일반 삭제 확인 문구만 표시.

## 관리자 화면 (`/admin` 하위)

### `/admin/members`

- 이름, 별칭 목록(쉼표 구분 입력 → `text[]` 변환), 역할, 활성 여부.
- 삭제 대신 `is_active = false`로 처리(과거 회차 데이터의 참조 무결성 보존).

### `/admin/books`

- 제목, 저자, 표지 URL, 메모.

### `/admin/sessions`

- 책, 모임일, 마감일, 책 선정자, 진행자, 상태(`draft`/`open`/`closed`).

### `/admin/sessions/[id]/topics`

- 논제 추가/수정/삭제, 순번은 숫자 입력으로 정렬.
- 유형 선택: `free`/`excerpt`/`choice`.
- 담당자 지정(선택), 별점 표시 여부 체크박스.
- `choice` 유형은 목록에는 나타나지만 전용 편집 UI는 MVP에서 만들지 않는다.
- 답변이 이미 달린 논제를 삭제하려는 시도는 경고 후 차단.

### 회차 템플릿 (`/admin/templates`)

매달 논제 1번(요약+별점)과 2번(발췌 나눔)이 사실상 고정이라는 관찰에서 나온 기능(자세한 배경은 RETENTION.md).

- 논제 묶음을 템플릿으로 저장.
- 새 회차 생성 시 "템플릿에서 시작" 선택 가능.
- 기본 템플릿 하나를 시드에 넣는다: 1) `free` · "책을 소개하는 한 문장 요약" · 담당=책 선정자 · 별점 있음, 2) `excerpt` · "인상 깊게 읽은 부분이나 발췌를 이유와 함께 소개해 주세요".
- 이전 회차를 골라 논제 구조만 복제하는 기능도 포함.

### 붙여넣기 일괄 이관 (`/admin/sessions/[id]/import`)

구글 문서에서 복사한 텍스트를 붙여넣으면 파싱한다. 파싱 규칙과 신뢰 경계는 SECURITY.md와 CLAUDE.md의 "붙여넣기 이관 파서" 절 참고. 흐름:

1. 텍스트 붙여넣기.
2. 서버가 파싱해 미리보기 표시(예: "논제 3개, 답변 15개, 사유더하기 22개를 만듭니다"). 이름 매칭에 실패한 항목은 목록으로 별도 표시하고, 관리자가 기존 멤버에 연결하거나 새로 만들지 선택.
3. 관리자가 확인 버튼을 눌러야 실제 저장이 일어난다. 미리보기 없이 즉시 저장되는 경로는 없다.

### 공통 원칙

- 모든 쓰기 작업은 Server Action이며 첫 줄에서 `requireAdmin()` 호출.
- 삭제 동작은 확인 모달을 거친다.

## 회차 상태 전이

```
draft → open → closed
        ↑________|   (관리자가 다시 open으로 되돌리는 것도 가능)
```

쓰기 권한은 상태별로 따로 분기하지 않고 **단일 규칙**을 따른다(DECISIONS.md 참고): **answers/replies의 생성·수정·삭제는 `session.status === 'open'`일 때만 서버가 허용한다.**

- `draft`: 관리자가 논제를 세팅 중. 참여자에게 회차 목록과 논제 내용은 보이지만(완전히 숨기지 않음), 답변/사유더하기 작성 UI는 비활성화되고 서버도 쓰기를 거부한다.
- `open`: 참여자가 답변/사유더하기 작성 가능. `/` 상단 카드에 노출.
- `closed`: 작성 마감. 조회(아카이브)는 계속 가능하지만 새 답변/사유더하기 작성과 기존 것의 수정은 서버가 완전히 거부한다. 늦참자를 구제하려면 관리자가 상태를 다시 `open`으로 되돌려야 한다 — 별도의 "재오픈" 기능을 새로 만들지 않고 기존 상태 변경으로 처리한다.

## v2 범위 (스키마만 반영, 화면 없음)

- 블라인드 제출: 본인 제출 전 타인 답변 잠금(`sessions.blind_enabled`).
- `choice` 논제 찬반 투표(`votes` 테이블).
- 마크다운 내보내기.
- 전문 검색.

MVP는 화면만 줄이고 스키마는 v2까지 담아둔다 — 나중에 마이그레이션 없이 기능을 켤 수 있게 하기 위함.
